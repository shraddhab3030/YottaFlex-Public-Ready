# YottaFlex schema version 2 - complete field dictionary

This document describes structural SQL storage. Runtime workflow rules are
implemented in workflow.py, evaluation.py and offers.py; SQL-only annotations
remain distinct from those business gates. Generated by `PYTHONPATH=src .venv/bin/python3 scripts/build_data_dictionary.py`
from annotated schema.sql and SQLite PRAGMAs; `--check` verifies no drift. The
integrity tests verify every table/column is represented. No domain data is used.

## Conventions and lifecycle semantics

- Tables use SQLite STRICT storage; SchemaMetadata is also WITHOUT ROWID so its
  singleton integer key cannot be implicitly allocated on NULL. Every field has explicit nullability;
  NULL means optional/unknown/not yet applicable, never a magic empty string.
- All time fields are INTEGER UTC Unix epoch seconds, inclusive range
  0..253402300799 (1970-01-01 through 9999-12-31). Whole seconds only; no local
  time, float or date string. This refines Phase 01's proposed ISO text into the
  single epoch convention expressly permitted by Phase 02. Human display is IST.
- Effective/booking intervals are half-open [start,end). End must exceed start;
  NULL valid_to means open-ended. Cross-row scheduling and effective-date rules are enforced by workflow operations/validators.
- Monetary amounts are INTEGER minor units with a fixed scale of 100 per major
  currency unit in this synthetic dataset. Currency is three uppercase letters,
  not a claim that every code is an externally verified ISO currency. Offer
  currency/requisition must match its FK-linked historical band snapshot. Runtime
  band/approval eligibility is enforced by offers.py and independent validators.
- Raw rubric scores/skill levels are INTEGER 0..4, weights 1..10000 basis points,
  derived totals optional 0..4000 thousandths of a rubric point. SQL scalar ranges are supplemented by the implemented evaluation arithmetic,
  version/relevance/completion gates and independent reconciliation.
- IDs use exact SQL CHECK patterns below; required six formats use positive
  six-digit counters and literal APP/SCORE composites. Additional prefixes are
  documented by each PK. Runtime IDs use deterministic zero-padded counters/composites; no random UUIDs.
- Core/support PK fields cannot change. Typed events, InterviewParticipant and
  SchemaMetadata are append-only: UPDATE/DELETE and replacement inserts rejected
  by triggers. Event uniqueness includes (entity,sequence); sequence continuity,
  projection agreement and historical policy are checked by implemented validators.
- Each event has a required Staff recording actor, including synthetic role=system,
  plus optional Candidate origin actor. Correlation IDs are opaque tokens, not
  unconstrained entity relationships. Subject/actor links use enforceable FKs.
- Each event also has a snapshot_json object for before/after scalar or structured
  non-key details (e.g. interview slots or scorecard items). SQLite checks valid
  JSON/object shape only; implemented workflow code validates payload semantics and
  appends snapshots transactionally. Do not put ground-truth labels in snapshots
  or hide relational keys there as a substitute for declared FKs.
- Projection rows hold current state. Workflow transactions append
  old/new event evidence atomically with mutation; schema does not automatically
  invent audit records or decide legal transitions. Master revisions use retained
  effective rows; band snapshots in RequisitionEvent anchor Offer references.
- Requisition/Offer/Approval/Scorecard/Candidate lifecycle enums are enumerated in
  their status rows. No legal transition graph is claimed by enum membership.
  Submitted/withdrawn/decided timestamps have same-row status consistency checks.

## Relationships and optionality

| Relationship | Cardinality / enforced structure vs runtime condition |
| --- | --- |
| Staff -> HiringManager -> Requisition | 1:0..1 manager profile, then 1:0..N roles; mandatory child FKs |
| Candidate <-> Requisition | N:M via Application, unique pair and exact composite ID |
| Requisition -> SkillRequirement / InterviewPanel | 1:0..N each; runtime generation validates criteria before approval |
| InterviewPanel <-> Staff | N:M via effective PanelMember; runtime overlap/membership-at-time guards |
| Staff -> Availability | 1:0..N; interval representation/range enforced, runtime availability coverage checks |
| Application / InterviewPanel -> Interview | each 1:0..N; composite FKs enforce the same requisition |
| Interview <-> Staff | N:M via immutable InterviewParticipant snapshots; runtime panel/role eligibility checks |
| Interview -> Scorecard | 1:0..N; unique reviewer pair and composite participant FK require assigned reviewer |
| Scorecard -> ScorecardItem | 1:0..N; each item references an existing criterion; runtime role relevance/version checks |
| Application -> Offer | 1:0..N; at most one final offer in pending_approval/approved/sent/accepted via partial UNIQUE index |
| RequisitionEvent -> Offer | band snapshot and offer share requisition/currency through composite FK; runtime amount/approved-status checks |
| Requisition OR Offer -> Approval | 1:0..N; each Approval targets exactly one, optional other FK must be NULL |
| Entity -> typed event | 1:0..N, required subject/Staff actor; optional originating Candidate |

Approvals require a request timestamp/reason and a decision timestamp exactly when
not pending. Appropriate staff authority, review prerequisites, effective panel
membership, completed scorecards and event/projection consistency use implemented
transactional business validation, not CHECK alone. All five mandatory anomaly
families have separate typed observations and an independent detector; ground
truth remains isolated from its inputs. See docs/phase06/anomaly-design.md.

## Initialization and versioning

Use yottaflex.db.connect so every supported connection enables foreign_keys and
recursive_triggers. initialize obtains BEGIN IMMEDIATE, creates only an empty
version-0 database, or verifies an identical version-2 database without resets.
SchemaMetadata records source/catalog SHA256; PRAGMA user_version is 2. Unknown,
modified, populated-unversioned schemas, active caller transactions and existing
FK errors are refused. DDL failure rolls back the entire new initialization.
No automatic migration or destructive reset exists. Future changes need an
explicit versioned migration, reviewed data preservation and migration tests.
Schema fingerprints detect accidental drift, not a malicious database owner who
can alter PRAGMAs/triggers/metadata. Keep database files local/private.

The following rows are generated from the actual SQL; full DDL (including table
checks/index predicates/immutability triggers) is included at the end for exact
auditability. Required means NOT NULL. Units 'none' means a categorical/text key.

    interview_id TEXT NOT NULL PRIMARY KEY CHECK (interview_id GLOB 'INT-2026-[0-9][0-9][0-9][0-9][0-9][0-9]' AND substr(interview_id, -6) <> '000000'), -- Immutable deterministic identity; six-digit positive counter | none
    application_id TEXT NOT NULL, -- Interviewed application | none
    panel_id TEXT NOT NULL, -- Selected panel | none
    requisition_id TEXT NOT NULL, -- Redundant FK join key to enforce panel/application share requisition | none
    start_at INTEGER NOT NULL CHECK (start_at BETWEEN 0 AND 253402300799), -- Scheduled start, inclusive | UTC epoch seconds; whole seconds, 1970..9999
    end_at INTEGER NOT NULL CHECK (end_at BETWEEN 0 AND 253402300799), -- Scheduled end, exclusive | UTC epoch seconds; whole seconds, 1970..9999
    status TEXT NOT NULL DEFAULT 'scheduled' CHECK (status IN ('scheduled', 'completed', 'cancelled', 'no_show')), -- Interview lifecycle | none
    FOREIGN KEY (application_id, requisition_id) REFERENCES Application (application_id, requisition_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    FOREIGN KEY (panel_id, requisition_id) REFERENCES InterviewPanel (panel_id, requisition_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    CHECK (end_at > start_at)
) STRICT;

-- table: Immutable snapshot of assigned interview members
CREATE TABLE InterviewParticipant (
    interview_id TEXT NOT NULL, -- Interview assignment | none
    staff_id TEXT NOT NULL, -- Assigned interviewer/reviewer | none
    assignment_role TEXT NOT NULL DEFAULT 'reviewer' CHECK (assignment_role IN ('reviewer', 'observer')), -- Immutable assignment kind | none
    assigned_at INTEGER NOT NULL CHECK (assigned_at BETWEEN 0 AND 253402300799), -- Snapshot recording time | UTC epoch seconds; whole seconds, 1970..9999
    PRIMARY KEY (interview_id, staff_id),
    FOREIGN KEY (interview_id) REFERENCES Interview (interview_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    FOREIGN KEY (staff_id) REFERENCES Staff (staff_id) ON UPDATE RESTRICT ON DELETE RESTRICT
) STRICT;

-- table: One structured scorecard per assigned reviewer/interview
CREATE TABLE Scorecard (
    scorecard_id TEXT NOT NULL PRIMARY KEY CHECK (scorecard_id = 'SCORE-' || interview_id || '-' || reviewer_staff_id), -- Immutable literal composite scorecard identity | none
    interview_id TEXT NOT NULL, -- Scored interview | none
    reviewer_staff_id TEXT NOT NULL, -- Assigned reviewer staff identity | none
    rubric_version INTEGER NOT NULL DEFAULT 1 CHECK (rubric_version >= 1), -- Rubric version used for scoring | count
    status TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'incomplete', 'submitted')), -- Scorecard lifecycle | none
    total_score_milli INTEGER CHECK (total_score_milli BETWEEN 0 AND 4000), -- Optional derived total; calculation deferred | thousandths of rubric point, 0..4000
    created_at INTEGER NOT NULL CHECK (created_at BETWEEN 0 AND 253402300799), -- Scorecard creation time | UTC epoch seconds; whole seconds, 1970..9999
    submitted_at INTEGER CHECK (submitted_at BETWEEN 0 AND 253402300799), -- Submission time | UTC epoch seconds; whole seconds, 1970..9999
    FOREIGN KEY (interview_id) REFERENCES Interview (interview_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    FOREIGN KEY (reviewer_staff_id) REFERENCES Staff (staff_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    FOREIGN KEY (interview_id, reviewer_staff_id) REFERENCES InterviewParticipant (interview_id, staff_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    UNIQUE (interview_id, reviewer_staff_id),
    CHECK (submitted_at IS NULL OR submitted_at >= created_at),
    CHECK ((status = 'submitted') = (submitted_at IS NOT NULL))
) STRICT;

-- table: Structured rubric evidence and criterion score
CREATE TABLE ScorecardItem (
    scorecard_id TEXT NOT NULL, -- Owning scorecard | none
    skill_requirement_id TEXT NOT NULL, -- Existing criterion; requisition applicability checked in later business validation | none
    score_value INTEGER CHECK (score_value BETWEEN 0 AND 4), -- Optional raw criterion score | integer rubric points 0..4
    weight_basis_points INTEGER NOT NULL CHECK (weight_basis_points BETWEEN 1 AND 10000), -- Snapshot weight; reconciliation deferred | basis points; 10000 = 100 percent
    evidence TEXT CHECK (length(trim(evidence)) > 0), -- Optional synthetic evaluation explanation | none
    status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'scored')), -- Item completion state | none
    PRIMARY KEY (scorecard_id, skill_requirement_id),
    FOREIGN KEY (scorecard_id) REFERENCES Scorecard (scorecard_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    FOREIGN KEY (skill_requirement_id) REFERENCES SkillRequirement (skill_requirement_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    CHECK ((status = 'scored') = (score_value IS NOT NULL))
) STRICT;

-- table: Offer projection; scalar amount validated, band eligibility remains business rule
CREATE TABLE Offer (
    offer_id TEXT NOT NULL PRIMARY KEY CHECK (offer_id GLOB 'OFF-2026-[0-9][0-9][0-9][0-9][0-9][0-9]' AND substr(offer_id, -6) <> '000000'), -- Immutable deterministic identity; six-digit positive counter | none
    application_id TEXT NOT NULL, -- Application receiving offer | none
    requisition_id TEXT NOT NULL, -- Join key for application and approved band event | none
    approved_requisition_event_id TEXT NOT NULL, -- Historical requisition band snapshot | none
    currency TEXT NOT NULL CHECK (currency GLOB '[A-Z][A-Z][A-Z]'), -- Currency must match referenced band snapshot | currency code; amounts in hundredths
    amount_minor INTEGER NOT NULL CHECK (amount_minor > 0), -- Offered compensation, not cross-record band check | integer minor currency units
    is_final INTEGER NOT NULL DEFAULT 1 CHECK (is_final IN (0, 1)), -- Final-offer indicator | boolean 0/1
    status TEXT NOT NULL DEFAULT 'draft' CHECK (status IN ('draft', 'pending_approval', 'approved', 'sent', 'accepted', 'declined', 'expired', 'rejected', 'withdrawn')), -- Offer lifecycle | none
    valid_from INTEGER NOT NULL CHECK (valid_from BETWEEN 0 AND 253402300799), -- Effective interval start, inclusive | UTC epoch seconds; whole seconds, 1970..9999
    valid_to INTEGER CHECK (valid_to BETWEEN 0 AND 253402300799), -- Effective interval end, exclusive; NULL means open-ended | UTC epoch seconds; whole seconds, 1970..9999
    FOREIGN KEY (application_id, requisition_id) REFERENCES Application (application_id, requisition_id) ON UPDATE RESTRICT ON DELETE RESTRICT,
    FOREIGN KEY (approved_requisition_event_id, requisition_id, currency) REFERENCES RequisitionEvent (event_id, requisition_id, currency) ON UPDATE RESTRICT ON DELETE RESTRICT,
    CHECK (valid_to IS NULL OR valid_to > valid_from)
) STRICT;

    status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'approved', 'rejected')), -- Approval lifecycle | none
    requested_at INTEGER NOT NULL CHECK (requested_at BETWEEN 0 AND 253402300799), -- Approval request time | UTC epoch seconds; whole seconds, 1970..9999
    decided_at INTEGER CHECK (decided_at BETWEEN 0 AND 253402300799), -- Decision time | UTC epoch seconds; whole seconds, 1970..9999
    reason_code TEXT NOT NULL CHECK (length(trim(reason_code)) > 0), -- Required reason/decision code | none
    valid_from INTEGER NOT NULL CHECK (valid_from BETWEEN 0 AND 253402300799), -- Effective interval start, inclusive | UTC epoch seconds; whole seconds, 1970..9999
    valid_to INTEGER CHECK (valid_to BETWEEN 0 AND 253402300799), -- Effective interval end, exclusive; NULL means open-ended | UTC epoch seconds; whole seconds, 1970..9999
